SUPPORT

Start with a safe diagnostic, not a secret.

Use the channel that matches the issue. Never post credentials, provider passwords, Cloudflare tokens, private keys, raw mail, or message content.

Documentation
Public bug reports

Product questions and bugs

Search or open a public issue in the GitHub issue tracker. Include the application version, browser, safe steps to reproduce, expected result, and actual result. Remove domains, addresses, request bodies, and identifiers that are not needed.

Workspace diagnostics

Owners and administrators can open Settings → Debug to view schema, provider health, last successful synchronization, failed-operation count, recovery-point state, and safe next actions. Review the report before sharing it and redact any customer-specific domain you do not want in a ticket.

Billing questions

AI subscriptions do not include technical support or a response-time promise. For a charge, cancellation, or refund issue, include the Stripe receipt identifier through the private billing path shown on the receipt, never full card details, credentials, or mail content.

Security reports

Do not publish an exploitable security issue. Use GitHub’s private vulnerability reporting when it is available for the repository. If that path is unavailable, open a non-sensitive issue asking for a private contact channel without disclosing the vulnerability.

Account deletion and refunds

See Account deletion for self-service removal and owner limitations. See Refunds for eligibility and timing.

Sovereign Mail does not install or manage customer deployments and does not provide on-call operations. Mail-provider and Cloudflare incidents remain controlled by those providers.
